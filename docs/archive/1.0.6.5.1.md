# 1.0.6.5.1 需求与修改归档

## 需求

修复 Windows 版安装包和便携版在启动后窗口无响应的问题，并保证后续发布不会把“窗口短暂出现后被启动任务卡住”的构建误判为可用。

## 原因与实现

- 受影响的旧便携包在启动阶段会同步恢复项目并触发内容同步；网络或磁盘等待落在 UI 路径时，窗口虽已创建但会持续失去响应。
- 当前源码已将最近项目恢复切换为后台任务，并把启动后的同步安排为后台检查；本次以 `1.0.6.5.1` 重新交付该修复后的源码。
- `smoke-portable.ps1` 与 `smoke-installers.ps1` 改为每 250 ms 采样一次，要求窗口句柄存在且连续 12 次（3 秒）保持 `Responding`；任一次失去响应均重新计时，最多观察 15 秒。
- 对外版本使用 `1.0.6.5.1`，运行时 SemVer 使用 `1.0.6+5.1`；版本解析与界面显示支持多段纯数字构建元数据。
- Windows Installer 只比较前三段，因此 WiX/MSI 改用 `1.0.6051`，确保能覆盖早先的 `1.0.6.5` 安装包；macOS bundle 构建号改为单调递增的 `1.1.0`。

## 接口变动

- 对外 Tauri 命令、事件、插件 API 与 AppConfigV3 配置格式均无变化。
- 发布脚本允许五段公开版本，例如 `1.0.6.5.1`；运行时版本仍保持标准 SemVer 格式。

## 验证与交付

本地预检、标签、平台工作流和公开资产复核结果见 [验证记录](../validation-1.0.6.5.1.md)。
