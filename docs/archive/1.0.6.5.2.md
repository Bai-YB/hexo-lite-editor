# 1.0.6.5.2 需求与修改归档

## 需求

1. 自动更新必须原地生效：一开始是便携包，更新后仍然留在便携包所在目录；用安装包安装并选择了目录（或使用默认目录），更新后仍回到同一个目录，不能更新到一个固定位置。
2. 桌面快捷方式：首次安装由用户选择是否创建，用户不选就不创建；之后每次更新都必须保证存在一个指向新版本的桌面快捷方式。
3. 修复本机已有的错误安装记录（安装位置指向 `%TEMP%`）。

## 原因与实现

- Windows 更新器只会运行发布页上的安装器。此前安装器按注册表里记录的安装位置安装：便携版没有这条记录，用户机器上残留的冒烟测试记录又把位置指向 `%TEMP%\hlex-installer-smoke-*\nsis`，于是新版本既不在原目录，桌面快捷方式也仍指向旧副本。
- `update.rs` 现在用 `installer_args` 把运行中可执行文件所在目录作为 NSIS `/D=<目录>` 传给安装器（`resolve_install_update`）。更新因此始终落在当前副本所在目录：便携包原地更新，安装版回到用户选择的目录或默认目录。
- 该参数只对 NSIS 安装包生效：更新地址不是 `-setup.exe`（例如 MSI）时，改用不含该参数的普通配置重新解析，避免把 NSIS 专用参数交给 `msiexec`。
- 新增 `src-tauri/nsis/hooks.nsh` 并通过 `bundle.windows.nsis.installerHooks` 接入。`NSIS_HOOK_POSTINSTALL` 在 `/UPDATE` 静默更新后确保桌面快捷方式存在并指向新二进制：先扫描桌面已有的 `.lnk`，若已有快捷方式指向当前二进制就重建它（刷新图标与目标），否则创建 `Hexo Lite Editor.lnk`，因此不会出现两个图标。
- 首次安装的快捷方式策略保持 Tauri 模板行为：交互安装时由完成页复选框决定（默认勾选，取消则不创建），静默首次安装仍然创建。
- `mainBinaryName` 统一为 `Hexo Lite Editor`，便携包与安装包的可执行文件同名，更新就不会在新旧文件名之间留下旧副本；旧版 `hexo-lite-editor.exe` 安装由安装器模板自行改名迁移并重定向快捷方式。
- `scripts/smoke-installers.ps1` 增加更新回归：首次静默安装后删除桌面快捷方式，再执行 `/S /UPDATE /D=<安装目录>`，断言 `Hexo Lite Editor.exe`、`resources` 仍在原目录，且桌面快捷方式已重建并指向该可执行文件；`finally` 同时清理卸载注册表项与临时目录，不再留下指向 `%TEMP%` 的安装记录。
- 本机清理：删除指向 `%TEMP%` 的卸载注册表项与残留的 `hlex-installer-smoke-*` / `Hexo Lite Editor-*-updater-*` 临时目录。

## 接口变动

- 对外 Tauri 命令、事件、插件 API 与配置格式无变化。
- 安装后的可执行文件名为 `Hexo Lite Editor.exe`（此前为 `hexo-lite-editor.exe`）；安装器会自动删除旧名称的二进制并重定向开始菜单与桌面快捷方式。
- 便携包内容不变，仍为 `Hexo Lite Editor.exe`、`resources/` 与 `README.txt`。
