# 1.0.6.4 需求与修改归档

## 需求

修复软件启动时短暂卡死；修复右侧即时预览无法展示文章内 HTML/CSS 效果；修复编辑器与预览侧边栏连续滚动后错位。同步检查不能卡住界面，设置页要给出清晰规划，并让用户明确选择 GitHub 或 WebDAV 后只显示对应配置。发布 Windows/macOS 1.0.6.4，发布后清理本地缓存。后续每次功能或版本修改都要更新模块职责、调用逻辑并归档版本内容。

## 实现

- 应用先加载配置并提交可交互首屏，更新状态和最近项目在第一帧后并行启动；取消启动时预加载全部页面模块。
- Tauri 的选择、恢复和打开项目命令改为 async，项目校验、同步状态读取、文章扫描、资源恢复和会话创建放入 `spawn_blocking`，避免占用 WebView/UI 线程。
- 已完成配置迁移的安装不再在每次启动时递归遍历旧应用目录；首次迁移写入完成标记，保留旧目录以便降级恢复。
- 即时预览通过跨 WebView 一致的轻量 CSS 块解析器处理文章 `<style>`：保留限定的展示规则、class、自定义变量、媒体查询与交互伪类，并将每条选择器限定在 `.markdown-preview`。外部导入、URL、脚本、事件、iframe、固定/粘性定位等继续删除。
- `renderMarkdownPreview()` 一次产生安全 HTML 与本地图片源；编辑器使用下一帧后的可取消任务合并快速输入，隐藏即时预览时不做无用解析。
- 滚动同步保留基于源码行的块锚点和动态布局重测，增加编辑器/预览首尾滚动范围直接对齐。预览交互会在浏览器真正改变滚动位置前取得主控权；锚点未就绪时延后反向映射，布局重测只使用已经映射的源码行，避免 CodeMirror 异步跳转尚未完成时被旧底部边界推回文末。
- 同步页重排为“选择通道 → 检查连接与差异 → 合并并持续同步”。GitHub/WebDAV 使用互斥选择卡，只挂载当前通道的表单；普通设置不再扫描项目，进入同步分类后先返回基础状态，再在后台统计范围。
- 同步状态、系统凭据读取/删除和关闭同步中的阻塞工作移入 Tauri blocking worker；开始网络或扫描操作前先提交可见进度，停止与重试保持原 generation 和任务锁约束。
- 新建 `docs/modules`，记录全项目模块地图，并详细说明启动、原生项目打开、HTML 预览、图片解析、滚动同步和发布调用链；版本单测将文档基线与当前版本绑定。
- 对外 `1.0.6.4` / 内部 `1.0.6+4` / MSI `1.0.6.4` / macOS bundle `1.0.604`。
