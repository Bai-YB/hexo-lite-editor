# 1.0.6.5.3 需求与修改归档

## 需求

1. macOS 上内容同步必须能在只读项目文件上正常工作，不能再出现 `恢复同步备份失败: Permission denied (os error 13)`，也不能因为一次失败留下的恢复日志而反复失败。
2. macOS 上必须正确识别用户已经安装的 Node.js；环境诊断与实际运行 Hexo 的判断标准要一致，确实缺少 Node.js 时给出安装方式。
3. 只发布 macOS 更新：Windows 用户不应收到本版本的更新提示。

## 原因与实现

### 同步在只读文件上失败

- 同步的「应用远端文件」「创建备份」「恢复备份」原本使用 `fs::write` / `fs::copy`，会打开目标文件本身写入。macOS（以及 POSIX）对只读文件（`0444`，常见于从 Windows 压缩包、共享盘或移动硬盘拷入的项目）直接返回 `EACCES`，即 `Permission denied (os error 13)`。编辑器自己的保存走的是「临时文件 + 改名」，只需要目录可写，所以只有同步会失败。
- 失败链路会放大问题：写入失败后回滚恢复备份同样失败，`apply-transaction.json` 被保留，之后每次同步或打开项目都会重试恢复并再次失败。
- 备份阶段还有一处连带缺陷：`remote.keys().chain(base.keys())` 会对同一路径复制两次，第二次覆盖的是刚写出的只读副本，在 Windows 上同样会失败。
- `platform/filesystem.rs` 新增 `replace_file_with_bytes` 与 `replace_file_from`：数据先写入同目录临时文件再改名到目标，只要求目录可写；Windows 上若因只读属性被拒，先清除该属性再重试一次。同步的应用、备份与回滚全部改用这两个函数，备份路径先做去重。
- 恢复备份前先比较内容，磁盘已经与备份一致时跳过写入；恢复目标仍执行与同步相同的符号链接校验；错误信息携带具体文件路径，权限类错误追加可操作的排查提示。

### 误报缺少 Node.js

- 运行 Hexo 时使用 `platform::command_path()`，它已为 Finder 启动的应用补齐 `/opt/homebrew/bin`、`/usr/local/bin`、`~/.nvm/versions/node/*/bin`、`~/.volta/bin`、pnpm/asdf/mise/fnm 等路径；但项目打开时的环境诊断直接用 `silent_command("node")`，继承的是 GUI 的最小 PATH，因此 Homebrew 或版本管理器安装的 Node.js 会被判为缺失。
- 命令探测统一收敛到 `platform::command_available`，诊断与执行共用同一套 PATH；缺少 Node.js 时的提示补充了安装方式（`brew install node` 或 nodejs.org）与「安装后重新打开项目」。
- 新增回归测试：候选路径覆盖 Homebrew 与各类版本管理器目录，命令探测与补齐后的 PATH 保持一致。

### macOS 专用发布通道

- 新增 `.github/workflows/finalize-macos-hotfix.yml`：只等待 `Build macOS` 成功，校验草稿 Release 只包含 macOS 资产，生成只声明 `darwin-x86_64` 与 `darwin-aarch64` 的 `latest.json`，校验更新包签名后把该 Release 公开并置为 Latest。
- Windows 用户在本版本为 Latest 期间手动检查更新会得到检查失败提示，不会下载或安装任何内容；下一次双平台发布会写回含 Windows 的 `latest.json` 并恢复正常。

## 接口变动

- 对外 Tauri 命令、事件、插件 API 与配置格式无变化。
- 同步备份目录结构、`apply-transaction.json` 格式与同步清单格式不变；先前失败的恢复日志可以由新版本正常回滚。
- 版本映射：对外 `1.0.6.5.3`，运行时 `1.0.6+5.3`，macOS bundle `1.1.2`；Windows MSI `1.0.6053` 只在下一次 Windows 构建时使用。
