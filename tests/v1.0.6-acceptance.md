## Update acceptance

- Local updater fixture returned valid newer, same, invalid, and binary responses.
- Binary response reported and returned 57 bytes.
- Download progress, unknown length, completion, and download-stage errors are covered by Rust tests.
- Tauri download verifies the signed package before caching it; installation is a separate guarded action.
- Repository-specific updater public key is configured; the matching private key and password are GitHub Actions secrets.
- Windows and macOS workflows publish signed updater artifacts and compose the final cross-platform `latest.json`.
- Release workflows parse as YAML; Windows and macOS publish installers, updater packages, signatures, manifests, and checksums.

## Plugin and language acceptance

- Enabled image-bed plugins are selectable as the editor's default provider and receive uploads in an isolated Worker.
- Plugin network access remains behind manifest permission checks and the bounded backend HTTP command.
- Enabling a plugin requires a permission confirmation; JSON-schema settings can be edited and saved.
- Unit tests cover provider discovery and Worker entry exposure; E2E covers the plugin manager and cross-page English operation.
- English switching updates navigation, editor controls, image-bed controls, settings, plugins, About/update, dialogs, and accessibility labels without restart.

## Conditional / external verification

- CloudFlare-ImgBed has no official atomic empty-folder creation or folder-rename API. Those capabilities stay disabled instead of being emulated unsafely.
- A real signed upgrade installation still requires the v1.0.6 CI release artifacts; it cannot be completed from source-only fixtures.
- Windows 10/11 and macOS Intel/Apple Silicon installer behavior must be confirmed on those target machines after CI packaging.
- The main workflows are operable in English and covered across pages. Some long legacy descriptions and demo/user content remain Chinese, so a strict source-level zero-Chinese audit is still conditional.
- Plugin provider upload covers picker, paste, and native file-drop input. Dropped paths are validated and read by a narrow backend bridge before bytes enter the Worker; arbitrary filesystem access is not exposed.
- Article rename atomically updates local title, file name, and `imgbed_folder`; automatic remote folder migration/link rewrite remains conditional on upstream gaining a safe folder-rename API.
